# Changelog

## Unreleased

### Features

* **offers:** `kraty.offers` (`OffersClient`): `list(externalPlayerId, { limit?, level? })` and `trigger(externalPlayerId, input, { playerContext?, idempotencyKey? })` for real-money offers (docs/26), with the `Offer`, `OfferTier`, `OfferState`, `OfferTriggerInput` and `OfferTriggerResult` types. `purchases.track` takes `offerInstanceId` (the verified door for an offer purchase) and its result carries `offer` (`PurchaseOfferResult`).
* **offers:** free chain tiers. `offers.claim(externalPlayerId, instanceId, { tier, idempotencyKey? })` claims the current free step of a chain offer for server-driven storefronts (`OfferClaimResult { claim, offer }`; a refusal is a `conflict` error with `details.reason` `tier_changed` / `tier_not_free` / `offer_closed`). `OfferTier` gains `type: 'paid' | 'free'` and `storeProductKey` is now `string | null` (null on a free tier, `skus: {}`, `referencePriceMinor: 0`). New types `OfferTierType`, `OfferClaim`, `OfferClaimResult`, `OfferClaimRefusalReason`.
* **offers:** Revision 4 (additive). `Offer` gains `variantKey` (the A/B variant the player sees, already applied to `current`, `next` and `presentation`) and `linkedEventKey` (the linked event's key, or null); `OfferClaim.variantKey` and `PurchaseOfferResult.variantKey` name the variant that was claimed or sold. `offers.list` already applies the game-wide offer caps (at most the game's "listed at once", highest priority first). Always present, null when unused.
* **offers:** delivery default, no API change. New offers default to Kraty delivering their contents (`delivery.grantContents: true`): Kraty grants them (`offer.granted`, `grant.created`; `offer.pendingVerification` until your server reports the purchase verified, test players on test keys at once) and `offer.studioFulfils` is false, so the game must not grant them too. Deliver `offer.contents` / `claim.contents` yourself only when `studioFulfils` is true (offers switched to "Game delivers"). Existing offers keep their setting.
* **events:** new server-side gate reasons, no API change. Events and offers can gate on in-game currency the player spent (`currency_spent_at_least`) and on days since install (`days_since_install_at_least`); a refused `start` carries `unlock_condition_failed` / `entry_requirement_failed` as before, with a message like `spent 12,500 / 1,000,000 diamonds` or `installed 12 / 100 days ago`. The rules are evaluated by Kraty only; nothing to send from the client.
